Lightweight, zero-dependency Go background service & HTTP shield for Linux and Windows. Prevents, detects, logs, and mitigates php2shell pre-auth RCE exploits across PHP 5.4–8.5 without requiring application code changes.

Quick Install (Linux & Windows)

Default install is out-of-band. The installer starts the session, process, log, and hardening guards without changing web ports. The in-line HTTP WAF is opt-in: set proxy_enabled: true and a real backend_url, then route public traffic to listen_addr. Never enable the proxy against a placeholder backend — clients will receive 502.

Option A: One-Line Installer (Downloads binary, audits PHP, installs & starts systemd service)

Deployment Modes

      

        Choose out-of-band host protection, in-line HTTP inspection, or both. The
        proxy is intentionally disabled by default so a fresh install
        cannot break a host whose PHP backend is not on a guessed address.
      

      

        
          

            Mode
            How to run
            Protects
            Traffic change
          

        
        
          

            Out-of-band (default)
            sentinel install / sentinel run
            Session poisoning, spawned shells, runaway workers, crash/OOM log signals, php.ini hardening, optional firewall bans
            None
          

          

            In-line WAF
            sentinel run -proxy -listen 127.0.0.1:8080 -backend http://127.0.0.1:8081
            All out-of-band protections plus pre-parser blocking of multipart, request, cookie, response, and scanner vectors
            Route public traffic to listen_addr; keep the PHP backend private
          

        
      


      

        
Enable the in-line shield

        

          Point backend_url at the real PHP listener (FPM, Apache, nginx,
          or IIS), then route public traffic to listen_addr.
        

        

          
# /etc/php2shell-sentinel/sentinel.json
"proxy_enabled": true,
"listen_addr": "127.0.0.1:8080",
"backend_url": "http://127.0.0.1:8081"

# restart, then confirm the backend is reachable
sudo systemctl restart php2shell-sentinel
sudo journalctl -u php2shell-sentinel -n 20
curl -s http://127.0.0.1:9095/status

        

        

          If the backend is unreachable, Sentinel logs
          backend_unreachable and the proxy returns
          502. Fix backend_url, or run with
          -no-proxy if only out-of-band protection is intended.

        Limitations: normal process sampling runs every 150ms;
        a malicious WAF finding triggers a 10ms burst for 5s so short-lived
        system('id') children are far more likely to be caught.
        Common PHP version strings are scrubbed from small, uncompressed
        text/JSON/XML responses (scrub_php_version_in_body), but
        large, compressed, or non-text output is still application-owned.
        A scanner may report INCONCLUSIVE when its probe is
        rejected with 403; that is expected — the probe never
        reached PHP. The 3-probe/60s quarantine is configurable
        (probe_threshold, probe_window). Sentinel is
        mitigation, not a substitute for patching PHP and disabling
        session.upload_progress.enabled.
      

    


    
    

      
What Works with "Zero Application Modifications"

      

        Sentinel can run as an in-line HTTP reverse proxy shield or completely out-of-band (-no-proxy -firewall) without altering existing Apache, Nginx, IIS, or PHP ports.
      

      

        
          

            Capability
            How Sentinel Does It Passively
            App Changes?
          

        
        
          

            Blocking Spawned Shells
            Scans OS process tree (/proc on Linux, Win32 CreateToolhelp32Snapshot on Windows) every 150ms, with a 10ms burst for 5s after a WAF finding and kills shells (sh, bash, cmd.exe, powershell.exe, nc, curl) spawned by PHP workers.
            No
          

          

            Deleting Poisoned Sessions
            Watches /var/lib/php/sessions, /tmp, C:\Windows\Temp, and C:\xampp\tmp for sess_* files containing <?php, upload_progress_ state, |O:/|C: object gadgets, or > 4 MiB inflation and quarantines/deletes them immediately. Legitimate upload_progress_...|a: arrays are cleaned as upload state, not mislabelled as handler mismatch.
            No
          

          

            Detecting Crashes & OOM Bailouts
            Reads directly from journalctl (Linux), Windows Application Event Log (wevtutil), and web error logs for in Unknown on line 0, Session object destruction failed, and SIGSEGV.
            No
          

          

            Quarantining Attacking IPs
            Automatically inserts DROP/Block rules into the OS firewall (iptables on Linux, netsh advfirewall on Windows).
            No
          

          

            Deep Multipart UAF Prevention
            When run in-line, aborts PHP_SESSION_UPLOAD_PROGRESS, blocks two-phase stalled uploads (< 900ms chunk timeout), caps per-IP concurrent multipart connections (defeating 149-worker pinning), and scrubs Set-Cookie: PHPSESSID heap leaks.
            Point HTTP backend
          

        
      

    


    
    

      
CLI & Service Operations Reference

      

        
Linux Commands

        

          
          
# Audit local PHP version & php.ini files (read-only)
sentinel check

# Apply virtual patches (session.upload_progress.enabled = Off) with .bak backup
sudo sentinel harden

# Run in Zero-Touch Out-of-Band Mode (watches /proc, sessions, journald & iptables)
sudo sentinel run -no-proxy -firewall -log-file /var/log/php2shell-sentinel.log

# Check systemd service status, live telemetry & journal logs
sudo systemctl status php2shell-sentinel
sudo journalctl -u php2shell-sentinel -f
sentinel status

        


        
Windows Commands (Elevated PowerShell / Administrator CMD)

        

          
          
# Audit local Windows PHP installation (XAMPP / WAMP / Laragon / IIS)
sentinel.exe check -path C:\xampp\php

# Apply php.ini virtual patches with automatic .bak backup
sentinel.exe harden -path C:\xampp\php\php.ini

# Run in Zero-Touch Out-of-Band Mode on Windows (Win32 processes, sess_*, Event Log, Windows Firewall)
sentinel.exe run -no-proxy -firewall -log-file C:\ProgramData\php2shell-sentinel\sentinel.log

# Query Windows Service status, live telemetry, and Windows Firewall rules
Get-Service PHP2ShellSentinel
sc.exe query PHP2ShellSentinel
sentinel.exe status
netsh advfirewall firewall show rule name=all | findstr PHP2ShellSentinel

        

      

    


    
    

      
Built-In Detection & Mitigation Rules

      

        
          

            Rule ID
            CVE / Chain
            Target Vector & Mitigation
          

        
        
          

            P2S-2026100
            CVE-2026-109618 / 109619
            Blocks or strips PHP_SESSION_UPLOAD_PROGRESS in POST/PUT/PATCH multipart bodies (including multipart/form-data,boundary=x).
          

          

            P2S-2026100-STALL
            CVE-2026-109618 / 109619
            Aborts stalled multipart uploads (> 900ms inter-chunk pause) before php_session_track_init() frees arData.
          

          

            P2S-2026100-STREAM
            CVE-2026-109618 / 109619
            Sliding-window scanning of large multipart uploads with pooled buffers, preventing padding bypasses before PHP parses the body.
          

          

            P2S-2026101
            PR #22113
            Blocks name="PHPSESSID" in multipart request bodies (prevents session.use_only_cookies bypass).
          

          

            P2S-2026102
            Chain A (Session LFI)
            Blocks PHP tags (<?php, <?=) inside multipart upload filenames.
          

          

            P2S-2026103
            Chain C (Handler Mismatch)
            Blocks |O:... / |C:... serialized object injection inside upload filenames. Plain serialized arrays (|a:) used by upload-progress state are not treated as object gadgets.
          

          

            P2S-2026104
            Chain E & Heap Spray
            Blocks upload filenames > 200 bytes (stops 231B ZendMM 256B bin spray and 10KB+ session inflation).
          

          

            P2S-2026105
            Chain D (SAPI OOM)
            Blocks Transfer-Encoding: chunked on multipart uploads (post_max_size bypass) and excessive part counts.
          

          

            P2S-2026106
            Chain A (LFI / pearcmd)
            Blocks LFI paths referencing sess_* or pearcmd.php (+config-create+).
          

          

            P2S-2026107 / 108
            Scanner / Heap Shape
            Blocks a[][a][a]... nested bracket probes and empty-boundary discrepancy probes; auto-bans after 3 probes/60s (configurable).
          

          

            P2S-2026109 / 111 / 112
            Pure HTTP ASLR Bypass & Response Guard
            Blocks forged binary Cookie: PHPSESSID pointers, scrubs 800KB Set-Cookie: PHPSESSID heap leaks, and quarantines Session object destruction failed / PHP OOM responses.
          

          

            P2S-2026116
            Version Disclosure Scrub
            Replaces PHP 8.x.y / PHP Version 8.x.y strings in small, uncompressed text, JSON, and XML responses and fixes Content-Length.
          

          

            P2S-20244577
            CVE-2024-4577
            Blocks PHP-CGI soft-hyphen (%ADd) and -d allow_url_include / auto_prepend_file argument injection.
